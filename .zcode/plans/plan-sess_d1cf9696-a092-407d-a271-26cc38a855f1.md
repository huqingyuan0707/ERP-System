## Context
GitHub 的 AI 评审因改动触及迁移、鉴权、库存和 CI 而按路径规则判为高风险，并且评审正文明确承认关键 diff 被截断。只读核对显示多数红／橙项是“无法确认”的泛化告警，而不是现有实现缺失：

- `f2b6c8d0e1a3` 在任何 DDL 前执行 preflight；重复和非规范键会 `raise RuntimeError`，跨租户引用／历史数值仅按设计报告 ID、不改数据；迁移和降级有专项测试。
- 库存先锁仓库、商品、单位、库存行，禁止负可用库存，与流水同事务；`IdempotencyService.execute()` 使用持久化表、数据库唯一键和同事务结果缓存。
- 基础资料按需求默认租户内全部可见；库存 V1 按仓库筛选，不要求本人／本部门范围。通用采购／销售／财务报表数据未接入时已明确拒绝，不生成占位文件。
- 商品／库存导出使用各自模块权限，任务、下载和数据查询按 tenant／owner 隔离；Excel 是文件生成，不是 API 返回 ORM 对象。
- `ExportButton.vue` 没有模板中的 `void` 表达式，props 对象默认值使用工厂，`vue-tsc`、ESLint 和生产构建均已通过。

不过评审揭示了值得补强的真实发布门禁：生产默认密钥／占位数据库配置尚未 fail-fast；PostgreSQL CI 只验证迁移，没有运行库存／幂等并发用例；迁移回滚目标硬编码；权限或数据范围变更后的缓存策略需要有明确测试证据。

## 1. 补生产配置安全门禁
- 在 `backend/app/core/config.py` 增加 Pydantic 配置校验：
  - `TESTING=true` 保持现有隔离行为；测试密钥可用固定测试值。
  - 非测试环境禁止 `SECRET_KEY=change_me`、过短／常见占位密钥。
  - 非测试环境禁止数据库连接串仍含 `change_me`；保留 `.env.example` 中本地开发明确值，部署脚本生成强密钥的现有流程不变。
  - `REDIS_URL` 为空继续作为受支持的进程内缓存降级，不错误阻断；在启动日志中明确说明降级状态。
- 增加配置单测，覆盖测试模式、弱密钥、占位数据库密码、合法生产配置和空 Redis。
- 更新 `.env.example`／部署文档的安全说明，避免用户复制占位值后应用才启动失败而不知原因。

## 2. 让 PostgreSQL CI 验证真正的库存与幂等并发
- 在测试中增加 PostgreSQL marker，新增真实多会话并发用例：
  - 两个事务并发出库／锁定，最多一个成功且库存、可用量、流水一致，无负库存。
  - 同一幂等键并发提交，业务只执行一次；一个成功、另一个返回受控 409 或重放成功结果，不产生重复流水。
  - 商品删除／换单位与库存写入并发，验证商品行锁及统一锁序，不留下“已删除商品有库存”或精度不兼容库存。
- CI 的 SQLite 3.11/3.12 矩阵继续运行普通快速测试；PostgreSQL 16 job 除迁移外运行 `-m postgres` 的并发／方言专项，名称明确区分。
- 如果测试依赖外部 PostgreSQL，则仅使用 CI 临时库；本地无 Docker 时如实跳过，不连接已有数据库。
