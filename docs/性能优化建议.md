# 性能优化建议

本文档提供ERP系统的性能优化建议和最佳实践。

## 数据库优化

### 连接池配置

当前配置（生产环境）：
```python
pool_size=5          # 基础连接数
max_overflow=10      # 最大溢出连接数
pool_recycle=3600    # 连接回收时间（1小时）
```

**调整建议：**
- 高并发场景：pool_size=10, max_overflow=20
- 低并发场景：pool_size=3, max_overflow=5
- 监控连接池使用率，动态调整

### 索引优化建议

#### 高频查询索引

1. **租户隔离索引**（已存在）
   - 所有业务表都有 `ix_{table}_tenant_id`
   - 确保租户过滤查询高效

2. **组合索引建议**
   ```sql
   -- 用户登录：username + tenant_id + is_deleted
   CREATE INDEX ix_sys_user_login ON sys_user(username, tenant_id) 
   WHERE is_deleted = false;
   
   -- 库存查询：warehouse_id + goods_id + tenant_id
   CREATE INDEX ix_inv_stock_query ON inv_stock(warehouse_id, goods_id, tenant_id)
   WHERE is_deleted = false;
   ```

3. **避免过度索引**
   - 每个表索引不超过5个
   - 定期分析未使用的索引
   - 使用EXPLAIN ANALYZE验证查询计划

### 查询优化

#### N+1查询优化

**问题模式：**
```python
# 不好的做法：循环查询
for user in users:
    roles = await get_user_roles(user.id)  # N+1查询
```

**优化方案：**
```python
# 使用JOIN一次性获取
stmt = select(User, Role).join(UserRole).where(...)
result = await db.execute(stmt)
```

#### 分页优化

**大数据量分页：**
```python
# 使用游标分页代替OFFSET
async def list_items(cursor: int | None = None, limit: int = 50):
    stmt = select(Item).order_by(Item.id)
    if cursor:
        stmt = stmt.where(Item.id > cursor)
    stmt = stmt.limit(limit)
    return await db.execute(stmt)
```

### 批量操作优化

#### 批量插入
```python
# 使用bulk_insert_mappings
await db.execute(
    bulk_insert_mappings(Item, items_data)
)
```

#### 批量更新
```python
# 使用update语句批量更新
await db.execute(
    update(Item)
    .where(Item.category_id == category_id)
    .values(status=1)
)
```

## 缓存策略

### Redis缓存建议

#### 缓存层级

1. **L1缓存（内存）** - 应用进程内缓存
   - 配置数据、字典数据
   - TTL: 5分钟

2. **L2缓存（Redis）** - 分布式缓存
   - 用户权限、基础数据
   - TTL: 30分钟

#### 缓存场景

```python
# 字典数据缓存
@cache(ttl=300)
async def get_dict_items(dict_type: str):
    return await repository.list_items(dict_type)

# 用户权限缓存
@cache(ttl=1800, key_builder=lambda user_id: f"user_perms:{user_id}")
async def get_user_permissions(user_id: int):
    return await repository.list_permissions(user_id)
```

#### 缓存失效策略

1. **主动失效** - 数据更新时删除缓存
2. **TTL失效** - 设置合理的过期时间
3. **Write-through** - 写入时同步更新缓存

### 缓存注意事项

1. **缓存穿透** - 对不存在的key也缓存空值
2. **缓存雪崩** - TTL设置随机值，避免同时失效
3. **缓存击穿** - 热点key使用互斥锁

## 应用层优化

### 异步处理

#### 耗时操作异步化

```python
# 导出等耗时操作使用任务队列
async def export_data(query):
    task_id = await create_task("export", query)
    return {"task_id": task_id, "status": "processing"}
```

### 批量接口优化

#### 批量查询接口

```python
# 提供批量查询接口，减少请求次数
@router.post("/batch")
async def batch_get(item_ids: list[int]):
    results = await repository.batch_get(item_ids)
    return results
```

### 分页优化

#### 游标分页

```python
# 对于大数据量，使用游标分页代替OFFSET
async def list_items(last_id: int | None = None, limit: int = 50):
    stmt = select(Item).order_by(Item.id)
    if last_id:
        stmt = stmt.where(Item.id > last_id)
    stmt = stmt.limit(limit)
    return await db.execute(stmt)
```

## 监控与调优

### 慢查询监控

#### 启用慢查询日志

```python
# PostgreSQL配置
log_min_duration_statement = 1000  # 记录超过1秒的查询
```

#### 定期分析慢查询

```sql
-- 查找慢查询
SELECT query, mean_exec_time, calls
FROM pg_stat_statements
WHERE mean_exec_time > 100
ORDER BY mean_exec_time DESC
LIMIT 10;
```

### 性能指标

#### 关键指标

1. **响应时间** - P50 < 200ms, P95 < 500ms, P99 < 1s
2. **吞吐量** - QPS > 100
3. **数据库连接池使用率** - < 80%
4. **慢查询比例** - < 1%

#### 监控工具

1. **APM工具** - Sentry, Datadog
2. **数据库监控** - pg_stat_statements
3. **应用监控** - Prometheus + Grafana

## 常见性能问题

### 问题1：N+1查询

**症状：** 单个请求执行大量SQL

**解决方案：**
- 使用JOIN预加载
- 使用selectinload
- 批量查询

### 问题2：缺少索引

**症状：** 查询响应慢，EXPLAIN显示Seq Scan

**解决方案：**
- 添加合适的索引
- 使用组合索引
- 避免过度索引

### 问题3：大事务

**症状：** 锁等待时间长，死锁

**解决方案：**
- 缩小事务范围
- 避免长事务
- 优化SQL执行顺序

### 问题4：连接池耗尽

**症状：** 应用无法获取数据库连接

**解决方案：**
- 增加连接池大小
- 检查连接泄漏
- 优化查询响应时间
