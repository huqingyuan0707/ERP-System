## 二、服务器准备

```bash
# 1) 安装 Docker + compose 插件
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker

# 2) 2G 内存必须加 swap，否则构建/运行容易被 OOM 杀掉
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

# 3) 防火墙放通：22(SSH) 80(HTTP) 443(HTTPS)
#    MinIO 的 9000/9001 本项目未使用，无需放通
```

克隆代码（使用只读 Deploy key，服务器上不放 PAT）：

```bash
ssh-keygen -t ed25519 -f /root/.ssh/deploy_key -N ""     # 一次性生成
cat /root/.ssh/deploy_key.pub >> /root/.ssh/authorized_keys
cat >> /root/.ssh/config <<'EOF'
Host github.com
  IdentityFile /root/.ssh/deploy_key
  StrictHostKeyChecking accept-new
EOF

git clone git@github.com:huqingyuan0707/ERP-System.git /root/erp
```

把公钥（`deploy_key.pub`）添加到 GitHub 仓库的 **Settings → Deploy keys**（只勾 Read 即可）。

## 三、首次部署（服务器端）

```bash
cd /root/erp
cp .env.example .env                 # 基础配置
bash scripts/gen-env-secrets.sh .env  # 生成 DB_PASSWORD / SECRET_KEY 等强随机密钥
bash scripts/deploy.sh               # 构建并启动（compose 已是 ACR 镜像模式时改用下面的 CI 部署）
```

`scripts/gen-env-secrets.sh` 会把生成的 `DB_PASSWORD` **同步进 `DATABASE_URL`**，
否则 postgres 用新密码、后端仍用占位密码，会出现
`password authentication failed for user "erp"` 且后端无限重启。

若采用 ACR 镜像模式（CI 部署），服务器端需要 `.acr.env`（权限 600，**不入库**）：

```bash
umask 077
cat > /root/erp/.acr.env <<'EOF'
ACR_REGISTRY=crpi-zu5o46ticmciyebp.cn-beijing.personal.cr.aliyuncs.com/erpa
ACR_USERNAME=<ACR 访问凭证里的用户名>
ACR_PASSWORD=<ACR 固定密码>
EOF
chmod 600 /root/erp/.acr.env
```

自检：`bash scripts/check-env.sh`（检查配置、镜像可达性、容器状态、文件权限）。

## 四、GitHub Secrets 配置

仓库 → **Settings → Secrets and variables → Actions → New repository secret**。

| Secret | 必填 | 说明 |
|--------|------|------|
| `ACR_REGISTRY` | ✅ | `crpi-zu5o46ticmciyebp.cn-beijing.personal.cr.aliyuncs.com/erpa`（含命名空间）。也可用 `ACR_HOST` + `ACR_NAMESPACE` 拆分 |
| `ACR_USERNAME` | ✅ | ACR 实例「访问凭证」里的**用户名**（本环境是账号登录名，不是账号 ID） |
| `ACR_PASSWORD` | ✅ | ACR 固定密码 |
| `DEPLOY_HOST` | ✅ | `39.107.29.34` |
| `DEPLOY_USER` | ✅ | `root` |
| `DEPLOY_SSH_KEY` | ✅* | **SSH 私钥全文**（不是 `.pub`）。`*` 若改用 `DEPLOY_PASSWORD` 则可省略 |
| `DEPLOY_PASSWORD` | ❌ | 可选，服务器登录密码；配置后改用密码登录 |
| `DEPLOY_PORT` | ❌ | 可选，SSH 端口，默认 22（必须是纯数字） |
| `DEPLOY_REPO` | ❌ | 可选，`owner/repo`，默认 `huqingyuan0707/ERP-System`；fork/迁移时改这里 |
| `DEPLOY_REPO_TOKEN` | ❌ | 可选，仅当服务器还没有代码目录时用于自动 clone。推荐 **fine-grained token**（只需 `Contents: Read`） |
| `DEEPSEEK_API_KEY` | ❌ | AI 评审用的 DeepSeek 密钥；不配则跳过评审（或回退 `DASHSCOPE_API_KEY`） |

> **粘贴规范**：Secret 值里不要带尾随换行/空格。流水线会做清洗，但值里含空格易踩坑。
> 多行私钥建议 `base64 -w0 ~/.ssh/erp_deploy` 后填入，流水线会自动解码。

## 五、两条流水线

### 5.1 AI Code Review（`.github/workflows/ai-review.yml`）

| 触发 | 评审范围 | 结果发布到 |
|------|---------|-----------|
| 任意分支 `push`（仅代码文件，`*.md` 忽略） | 本次提交的增量 diff（`base..sha`） | **提交评论**（commit 页面 / PR Changes 里可见） |
| PR 打开 / 更新 | PR 全量 diff | **PR 评论** |

- 模型：DeepSeek `deepseek-chat`（未配置时回退通义千问 `qwen-plus`）。
- 输出分三类：🚫 严重问题 / 💡 建议改进 / ✅ 亮点。
- **只评论、不阻塞合并**。
- 退出码约定：无需评审（无变更/无密钥）→ 0；真正故障 → 非 0。

### 5.2 Deploy ERP（`.github/workflows/deploy.yml`）

`push` 到 `main` 或手动 `Run workflow` 时执行：

1. **解析并校验 ACR 配置**：清洗空白 → 校验域名/命名空间格式 → 未给命名空间时尝试自动探测 → 不合法立刻报明确错误。
2. **登录 ACR** → **预检镜像仓库** → **构建 backend/frontend 镜像** → **推送 ACR**（失败自动重试 3 次，命中限流等 30 秒）。
3. **SSH 部署**：把 ACR 地址/凭证写入服务器 `.env` 与 `.acr.env` → 执行 `scripts/update.sh`：
   `git fetch + reset --hard origin/main` → `docker compose pull` → `up -d` → 轮询 `/api/v1/health`。

也可以手动指定 tag（workflow_dispatch 的 `tag` 输入），部署非 latest 镜像。

#### 凭据传递的安全设计（重要）

- SSH 私钥**不写入 `$GITHUB_ENV`**：校验后写入运行器临时文件（600），通过 `key_path` 传给 ssh-action；
  并对私钥**逐行 `::add-mask::`**，任何日志输出都不会泄露。
- ACR 凭证、仓库 token 以 **base64 放进 step output**（不是全局环境变量），且 base64 值同样加掩码。
- clone 用的 token **不写进 URL 与命令行参数**：写入 600 权限的临时凭据文件，克隆后立即删除。
- 用户名/密码不通过 job output 传递（GitHub 会以「疑似密钥」为由拦截输出），改为原始 Secret + 远端清洗。

## 六、日常运维

```bash
cd /root/erp
docker compose ps                    # 服务状态
docker compose logs -f backend       # 后端日志
docker compose restart backend       # 重启单个服务
docker compose up -d --build         # 本地构建并重建（不走 CI 时用）
bash scripts/check-env.sh            # 环境自检
bash scripts/backup.sh               # 备份 PostgreSQL/Redis（默认保留 7 份）
bash scripts/setup-https.sh <域名>   # 申请并启用 HTTPS（需域名已解析到本机）
```

日常开发走 PR 流程即可，不要直接 push main：

```powershell
git checkout -b feature/xxx
git add . ; git commit -m "..." ; git push -u origin feature/xxx
# 在 GitHub 开 PR → AI 评审自动评论 → 修完合并 → 自动部署
```

## 七、故障排查速查（均为本次实际踩过的坑）

### 部署 / 构建

| 现象 | 根因 | 处理 |
|------|------|------|
| `Could not resolve hostname e:` | 在**服务器**上执行了 `scp e:\...`（本地路径） | `scp` 只能在本地机器执行；建议用 `tar` 打包或改用 git clone |
| `corepack ... ETIMEDOUT`（下载 pnpm 失败） | corepack 从 `registry.npmjs.org` 拉 pnpm 自身，国内不通 | `frontend/Dockerfile` 里加 `ENV COREPACK_NPM_REGISTRY=https://registry.npmmirror.com` |
| pip 安装极慢 | 走官方 PyPI | `backend/Dockerfile` 里加 `ENV PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/` |
| 后端无限 `Restarting (1)`，`password authentication failed for user "erp"` | `DATABASE_URL` 里仍是占位密码，与 postgres 实际密码不一致 | `scripts/gen-env-secrets.sh` 已修；手动修：把 `.env` 的 `DATABASE_URL` 密码段改成与 `DB_PASSWORD` 相同后 `docker compose up -d --force-recreate backend` |
| 访问首页显示 nginx 默认欢迎页 | 外层 nginx 用 `root` 找静态文件，但 dist 在 frontend 容器里 | 外层 nginx 改为 `location / { proxy_pass http://frontend:80; }` |
| 系统内页面 F5 刷新 404 | frontend 容器缺 history 路由回退 | `frontend/nginx.conf` + Dockerfile `COPY` 到 `default.conf`（已入仓库） |
| 登录接口 404 | 生产构建未注入 `VITE_API_BASE_URL` | 提供 `frontend/.env.production`（`VITE_API_BASE_URL=/api/v1`，**必须提交进仓库**） |
| 镜像名与 ACR 不一致导致拉取失败 | compose 用 `erp-backend`，ACR 里是 `erpa-backend` | 统一为 `erpa-backend` / `erpa-frontend`，或用 `BACKEND_IMAGE_REPO` 等变量覆盖 |

### ACR

| 现象 | 根因 | 处理 |
|------|------|------|
| `403 Forbidden` / `unauthorized` | 用共享版域名登录 | 个人版要用专属域名 `crpi-xxx.cn-<区域>.personal.cr.aliyuncs.com` |
| `unauthorized` 但域名正确 | 用户名填成了账号 ID | 用 ACR「访问凭证」页显示的用户名 |
| `denied: requested access to the resource is denied` | 命名空间下**没有对应镜像仓库** | ACR 不会在 `docker push` 时自动建仓库，需手动创建 `erpa-backend`、`erpa-frontend` |
| `no such manifest` | 仓库为空（还没推过镜像），属正常 | 忽略；推送后即可读 |

### GitHub Actions

| 现象 | 根因 | 处理 |
|------|------|------|
| push 被拒：`refusing to allow a PAT to create or update workflow` | PAT 缺 `workflow` 权限 | 重新生成令牌并勾选 `workflow` + `repo` |
| `Repository not found` | GitHub 用户名写错（`0907` vs `0707`） | 用 Settings → 账号 ID 处的正确用户名 |
| `Skip output 'x' since it may contain secret` | job output 的值与 Secret 相同，被 GitHub 拦截 | 不要用 output 传密钥；改用原始 Secret + 清洗 |
| `unexpected EOF while looking for matching "'"` | bash 双引号内的反引号被当成命令替换开始 | 用 `tr -d '[:space:]'` 清洗，别在双引号里放反引号 |
| 远端 `base64 -d` 失败、步骤秒退 | 模板写成 `{{ env.x }}` 少一个 `$` | 必须是 `${{ env.x }}` / `${{ steps.<id>.outputs.x }}` |
| `git clone --depth 1` 后 `git fetch` 失效 | 浅克隆限制 | 不用 `--depth`；`update.sh` 用 `fetch + reset --hard` |

### 本地 Git

| 现象 | 根因 | 处理 |
|------|------|------|
| `Failed to connect to github.com port 443` | 本地代理未启用 | 开启代理软件；或临时 `HTTPS_PROXY=http://127.0.0.1:<端口>` |

## 八、安全建议

1. **定期轮换密钥**：GitHub PAT、DeepSeek key、ACR 固定密码、服务器 root 密码建议各配一套并定期更换；
   PAT 用 classic 时只勾 `repo` + `workflow`，或改用 fine-grained token 限定到单仓库。
2. **不要把任何密钥写进仓库**：`.env` / `.acr.env` 已在 `.gitignore` 中；`frontend/.env.production` 虽入库但只含公开路径。
3. **对外暴露注意**：当前用 IP 直接访问，**无需域名也无需 ICP 备案**；但公网 IP 暴露后会被扫描，
   务必改掉默认口令 `admin / admin123`，必要时在 nginx 加访问白名单。
4. **镜像与依赖源**：国内服务器统一走 npmmirror / 阿里云 PyPI 镜像，避免构建超时。
