# 事务管理指南

本文档说明ERP系统中的数据库事务管理最佳实践和使用方法。

## 概述

系统提供了灵活的事务管理机制，支持以下两种模式：

1. **手动事务管理** - Service层使用 `commit` 参数控制事务边界
2. **事务上下文管理器** - 使用上下文管理器自动管理事务

## 手动事务管理（当前模式）

### 设计原理

Service层方法接受 `commit` 参数，允许调用方控制事务边界：

```python
async def my_service_method(self, payload, *, commit: bool = True) -> Result:
    """Service方法默认独立提交，但可通过commit=False由调用方控制。"""
    try:
        # 执行业务逻辑
        result = await self._do_something(payload)
        await self._db.flush()
        if commit:
            await self._db.commit()
        return result
    except Exception:
        if commit:
            await self._db.rollback()
        raise
```

### 使用场景

#### 场景1：独立事务（默认）

```python
# Service方法默认commit=True，自动提交
service = InventoryService(db, tenant_id=1)
result = await service.lock_stock(payload)
# 事务已自动提交
```

#### 场景2：事务包装器（幂等控制）

```python
# 幂等服务使用commit=False，在同一事务中执行业务和幂等键管理
idem_service = IdempotencyService(db)
result = await idem_service.execute(
    tenant_id=1,
    user_id=1,
    biz_type="lock_stock",
    idempotency_key="some-key",
    operation=lambda: inventory_service.lock_stock(payload, commit=False)
)
# 幂等键和库存操作在同一事务中提交
```

#### 场景3：复杂业务事务

```python
# 需要多个Service方法在同一事务中执行
async with db.begin():
    # 调用多个Service，都使用commit=False
    await inventory_service.lock_stock(payload1, commit=False)
    await inventory_service.change_stock(payload2, commit=False)
    await finance_service.create_voucher(payload3, commit=False)
    # 统一提交
```

### 最佳实践

1. **Service层方法签名**
   - 所有涉及数据库写入的方法都应接受 `commit: bool = True` 参数
   - 默认值为 `True`，支持独立提交
   - 幂等性方法使用 `commit=False`，由外层控制

2. **事务边界原则**
   - 单一Service操作：使用默认 `commit=True`
   - 幂等操作：使用 `commit=False`，由幂等包装器控制
   - 复杂业务：使用 `db.begin()` 上下文，所有Service使用 `commit=False`

3. **错误处理**
   - Service层不应吞没异常
   - 使用try-except确保commit失败时回滚
   - 保持异常传播，让调用方处理

## 事务上下文管理器（新增）

### 功能介绍

提供了三种事务管理工具：

1. **transaction上下文管理器** - 简单的自动提交/回滚
2. **@with_transaction装饰器** - 声明式事务管理
3. **TransactionManager类** - 细粒度手动控制

### 使用方式

#### 方式1：transaction上下文管理器

```python
from app.core.transaction import transaction

async with transaction(db):
    # 执行数据库操作
    result = await repository.add(entity)
    # 退出时自动提交，异常时自动回滚
```

#### 方式2：@with_transaction装饰器

```python
from app.core.transaction import with_transaction

@with_transaction(commit=True)
async def my_service_method(self, payload):
    # 方法结束时自动提交
    return await self._do_something(payload)
```

#### 方式3：TransactionManager类

```python
from app.core.transaction import TransactionManager

async with TransactionManager(db) as tm:
    # 执行操作
    result = await repository.add(entity)
    
    # 可手动控制提交时机
    if some_condition:
        await tm.commit()
    else:
        await tm.rollback()
```

### 迁移建议

当前系统使用手动事务管理，迁移到新方式需要谨慎：

1. **保持现有模式** - 当前 `commit` 参数模式已经工作良好
2. **新代码选择** - 新功能可以尝试使用事务上下文管理器
3. **逐步优化** - 在重构时评估是否替换为声明式管理

## 并发控制

### 行级锁

库存等关键操作使用SELECT FOR UPDATE：

```python
async def get_stock_for_update(self, warehouse_id: int, goods_id: int):
    stmt = (
        select(InvStock)
        .where(InvStock.warehouse_id == warehouse_id, ...)
        .with_for_update()  # 行级锁
        .execution_options(populate_existing=True)
    )
    return await self.db.scalar(stmt)
```

### Advisory锁

用于串行化写操作，防止重复：

```python
# PostgreSQL advisory锁
await db.execute(
    text("SELECT pg_advisory_xact_lock(hashtext('table_name'))")
)
```

### 死锁预防

1. **统一锁顺序** - 总是按相同顺序获取锁
2. **保持事务简短** - 减少锁持有时间
3. **设置超时** - 配置数据库锁超时时间

## 事务隔离级别

### PostgreSQL默认级别

PostgreSQL默认使用 READ COMMITTED，适合大多数场景。

### 可考虑的场景

1. **READ COMMITTED（默认）**
   - 适合大多数业务场景
   - 避免脏读，性能较好

2. **SERIALIZABLE**
   - 金融等需要严格一致性的场景
   - 性能开销较大，谨慎使用

### 设置隔离级别

```python
# 在特定事务中设置隔离级别
async with db.begin(isolation_level="SERIALIZABLE"):
    # 执行需要严格一致性的操作
    ...
```

## 事务监控

### 长事务检测

建议添加长事务监控：

```python
import time
from contextlib import asynccontextmanager

@asynccontextmanager
async def transaction_with_timeout(db: AsyncSession, timeout_seconds: int = 30):
    start = time.time()
    try:
        yield db
        await db.commit()
    finally:
        duration = time.time() - start
        if duration > timeout_seconds:
            # 记录告警日志
            logger.warning(f"Long transaction detected: {duration:.2f}s")
```

## 注意事项

1. **不要嵌套事务** - PostgreSQL不支持真正的嵌套事务
2. **避免过大事务** - 大事务会导致锁竞争和超时
3. **及时释放资源** - 使用async with确保连接释放
4. **测试回滚** - 确保异常场景能正确回滚
5. **注意异步上下文** - Service方法可能是被包装在更大事务中

## 常见问题

### Q: 什么时候使用commit=False？

A: 当方法需要被包含在更大的事务中时，如：
- 幂等键包装器
- 多个Service方法组合
- 测试场景需要回滚

### Q: 如何处理事务失败？

A: Service层应该抛出异常，由调用方决定是否重试或回滚：

```python
try:
    result = await service.method(payload)
except Exception as e:
    # 决定重试或返回错误
    if is_retryable(e):
        await service.method(payload)
    else:
        raise
```

### Q: 如何测试事务逻辑？

A: 使用commit=False进行测试，验证后回滚：

```python
async def test_inventory_lock():
    async with db.begin():
        # 执行操作
        result = await service.lock_stock(payload, commit=False)
        # 验证结果
        assert result.locked_qty > 0
        # 退出时自动回滚，不影响真实数据
```
